# QQ 上持续生活的角色

日常仍使用 `一键启动.bat`、`状态.bat`、`停止.bat`。主人私聊发送 `/重启` 会重新加载 Python 与 Bot 专用 DSH worker；无需重复点击启动。`/状态`、`/清空记忆` 是另外两个固定回复指令。其余对外正文由主角色生成。

## 运行链

QQ / NapCat → `bot.py` → `life.role_host` → Bot 专用 DSH SDK Agent → 工具、记忆与状态 → `life_say` → Delivery → QQ。

DSH 是唯一理解、选择与生成入口。Python 维护实际身份、事件、情绪与欲望、记忆范围、执行资格、送达回执和恢复。主角色可以直接查工具、读 skill、委派任务、保存偏好与自我叮嘱、修改人格和动力参数、提出可验证的代码发布。未处理的新消息会挡住继续派发副作用；用户停止的方向不会被自主唤醒复活。

普通聊天不需要先建立任务。长期方向保存为持续意图，阶段进展与整体结束分开。空闲时主角色根据当前状态选择探索、表达或继续休息，回复进行中不另开一套 Python 思考。

行动前可以直接做、先告知或先商量，沟通方式由主角色选择，不强制每件事报备。明确承诺等答复时，会把对应意图保存为 waiting，阻止相关后续执行；相应人物的新答复由主角色理解后恢复。等待不会因超时变成同意，其他无依赖的打算与聊天可以继续。

## 配置与数据

复制 `config.example.toml` 为 `config.toml`，填写主人账号、NapCat 连接和模型凭据。安装 Python 依赖使用 `.venv\Scripts\python.exe -m pip install -r requirements.txt`。本机 Node、DSH 工作副本及独立 home 路径见配置。桥通过受支持的 `dsh --profile sdk` 启动，桌面 DSH 的会话、插件和凭据不作为 Bot 数据清理目标。

`persona.md` 是唯一人格来源，使用 `persona:public` / `persona:private` 注释区块区分公共性格和专属私人内容。原有未分区的私人文件在首次启动时保守放进私密区，原公共内容保留为公共区。其他私聊和群聊使用自动投影的 `personas/public.md`，其源 hash 随普通性格和兴趣更新，不再手工维护第二份人格。可用 `target=persona_public` 修改公共部分。配置允许的群无需 @ 门槛；实际账号决定身份，私人记忆不会预先加载到群上下文。群工具默认关闭，可通过 `public_tools` 明确开放。

业务状态统一保存在 `data/life.db`；DSH 保存自身会话日志，发布器在 `data/life-control` 保存代码候选和部署状态。后二者用于会话持久化和独立发布，不是第二套意图或记忆数据库。旧 `brain.db`、`evo.db` 不参与生产入口。

行动额度默认每小时 500 步，每日不限；`action_per_hour`、`action_per_day` 为 0 表示不限。`resource_policy` 的默认空闲机会从 900 秒开始，每连续两次没有新变化延长一档，最多 7200 秒；新消息、真实结果和明确约定的短时任务不等空闲计时。她可以通过 `life_rest.next_attention` 自主安排再思考时间或暂时停止空闲计划。

关系的 familiarity、trust、comfort、bond 统一保存在 `life.db` 的 v2 `metrics` 中。主人各项范围为 0.7～1，其他人为 0～0.9；身份来自实际 QQ 账号和 `owner` 配置。初始 0.7 是政策位置，不表示已经积累亲密经历。自然对话中的关系影响由模型解释为方向、程度和置信度，宿主按版本、来源和实际边界结算；持久偏好与未解决事项单独保存，分数触底不会消除委屈或分歧。`life-dynamics.json` 的 `relations` 可校准幅度、敏感度、日累计和置信门槛，不能修改主人身份及范围政策。

用自然语言让她查看关系或 token 用量即可，不增加 QQ 指令。`life_read(kind=usage)` 区分未缓存输入、缓存读取、输出和推理子项；缺失统计和价格保持未知。DSH 的实际调用日志投影到同一 `life.db`，不混入 Codex 用量。文字工具大结果先给有界预览和原文引用，通过 `life_read(kind=observation)` 搜索或分页展开；多模态感知和程序使用的规范工具返回值不因文字预算被截坏。人格与方法放稳定规则，当前状态保留完整小快照；可选记忆初始预算为 1200 个估算 token。

表达使用独立于工具调用编号的答复归属：确认过的重试返回原回执，未知结果先对账，不换编号重发。明确的新表达可另开消息；用户重新要求发送也属于新输入。每个已确认片段单独进入共同经历，后续片段失败不会抹掉已说出的内容。子代理可以研究；账号上的公开表达由主角色采用后亲自执行。临时 RPC 故障由持久收件箱定期对账恢复，不依赖 DSH 进程退出。

Python 自升级支持多文件、新模块、核心业务和控制模块，以及兼容的加表、加列、加索引迁移。候选与独立验收先完成，发布绑定具体打算版本和来源；取消、修改、等待、新输入或遗忘会重新约束尚未激活的切换。实际切换支持部分进度恢复；代码回退不回退新生活数据。小型启动入口与独立测试由外部保留，不能靠同一候选删除失败断言来宣称改善。核心发布器变化会由启动器重启控制进程。破坏性数据库重构仍需单独交付兼容过渡，不通过回滚旧数据库实现。

图片、语音、引用和文件保留顺序及来源。音频使用本地 Whisper；首次使用会下载模型。视频可选择抽帧和转写，覆盖范围会注明。音色需真实试音验证后使用；当前 Edge 引擎支持预设声音及参数，不宣称支持任意声音克隆。

普通聊天按非空白字数在 2～5 秒内调整等待时间，最长 5 秒，回车可以形成多条消息。正文去掉首尾空白后达到 `paste_threshold`（默认 300 字符，含 300），保留全部回车整条发送，固定等待 4 秒；代码、列表、引用、表格及显式整条表达也按整体发送、等待 4 秒。首条同样遵守这套节奏。`typing_chars_per_second` 可调整短聊天的速度基准，等待时间仍限制在 2～5 秒。等待期间新输入仍会进入理解，过时表达不会继续发出。

DSH 会话文件策略和 Windows 权限分别生效。技术日志与主人私聊的运行材料会显示实际 worker 完整性；会话已是完全权限仍可能被 Windows 拒绝。QQ 中说“可以”表达授权，不会直接提升 Windows 进程权限。遇到这类限制应按实际诊断修复本机运行时，再 `/重启`，不需要重新点击启动。

## 日志与验证

- `data/conversation.log`：实际收到与确认发出的消息。
- `data/runtime.log`：运行、恢复与异常。
- `data/logs/dsh-bridge.log`：DSH worker 技术输出。

离线回归：`.venv\Scripts\python.exe -X utf8 audit/run_offline_suite.py`。真实模型、媒体和假通道集成脚本位于 `audit/run_*_smoke.py`；这些脚本的假通道不会发真实 QQ 消息。
