# 操作界面：看一眼 → 点 → 再确认

**所有手机操作都走这一条路，没有例外。** 不要算什么坐标，不要假设控件叫什么。

## 标准动作（`phone_tap` 内部就是这条）

```
1. 截一张图（同时拿到这张图的真实尺寸）
2. 找到目标：
     先让无障碍树按文字找（原生界面又快又准）
     找不到再问视觉「它在画面哪里」（自绘界面只能这样）
3. 点下去
4. 再截一张，和刚才那张比：
     画面变化 < 2% → 等于没点到 → 换一种方式再来
     变化够大 → 成功
5. 如果这一步有明确目的（比如「打开网络设置」），
   再让视觉确认一眼「画面上出现想要的东西了吗」
```

最多试 3 次，每次失败都换策略（视觉↔文字）。

## 为什么不能靠坐标

踩过的坑，一条条记着：

- 屏幕在 **900×1600** 和 **1600×900** 之间会翻，写死的坐标必然错位
- 无障碍树里会同时出现**两个窗口**（列表的 tab 在 y1519，聊天内容被挤到 y111）
- 有的按钮会报出**屏幕外坐标**（x=1433 但屏幕只有 900 宽）
- 打完字 **ADBKeyboard 会展开成全屏**，只剩一个「完成」，把整个界面盖住
- 界面**加载要时间**，刚 `open_app` 就问视觉，它会说「找不到」

## 各步骤该用什么

| 想做的事 | 用什么 |
|---|---|
| 知道屏幕上有什么 | `phone_look`（截图 + 文字）／`phone_see`（让视觉读出来） |
| 点某个东西 | `phone_tap`（文字优先，视觉兜底）／`phone_tap_see`（纯视觉） |
| 打字 | `phone_type`（打完自动收全屏输入框） |
| 滑动 | `phone_scroll` |
| 确认成没成 | 截图前后对比；必要时再问视觉 |

## 不要靠机械兜底

**别写"定时扫一遍、看到问题就自动修"这类东西。** 那是机器，不是人。

- 人会**看一眼确认**，不会定时扫
- 自动清扫会把她**刚打好、正准备发**的话一起清掉 —— 那就永远发不出去了
- 发不出去就**如实说**，然后**再看一眼屏幕**，看是哪儿不对，再决定怎么做

唯一该自动化的，是"看"这个动作本身。

## 一条重要的纪律

**别在没确认的情况下连着做下一步。** 前一步没成，后一步一定错。
宁可多截一张图，也别闭着眼睛往下点。

## 看视频 / 看动画：用连拍，别只看一帧

`phone_watch(seconds=6, times=3)` 会隔几秒连拍几张，再一起交给视觉。
单张截图只能看到一瞬间，中间"在动什么、翻到哪了"全丢。

## 看图的时候必须关思考

开着深度思考时，视觉请求会只返回推理、正文是空的（看着像"没看出来"）。
所有看图的地方都临时关掉思考。你自己写新功能时也要注意这一点。
