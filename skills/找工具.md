# 从能力缺口到实际解决

先理解要取得的真实结果，再查看当前 DSH 实际提供的工具。聊天、探索和研究使用同一套能力，不需要切换学习模式。本文里的名字不是工具已经存在的证明。

已有工具效果不好时，比较它返回的证据、覆盖范围、失败条件和替代办法。不要因一次成功就认定永远可靠，也不要按固定失败次数机械换工具。可以组合已有工具、阅读文档、寻找插件或编写脚本；仍不可行时再自然说明具体阻碍和需要的帮助。

装插件前查看来源、实际功能、依赖与如何核验。使用当前 DSH 的插件管理能力，目标是 Bot 的 SDK profile；不要改用户的桌面 profile。在已有授权内，根据事情和自己的意愿选择直接做、先告知或先商量。愿意等答复时保存该事项的等待；普通告知不自动等待，也不要求每个工具步骤都报备。

安装完成后检查有效工具集合，并实际完成一个相关的小任务。包出现在清单中不等于能力可用。独立人格、定时刷站或自动发消息的插件循环不应成为第二套主脑；优先接入它的工具原语，行动仍由当前主角色选择。

记录适用条件、真实用法、验证证据、失败条件与版本依赖；可保存为 skill 和带来源的经验，继续原目标。
