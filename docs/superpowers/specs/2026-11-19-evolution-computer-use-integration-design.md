# 小鱼浏览器与可回放技能接入设计

日期：2026-11-19（北京时间）

状态：云端方案修订版，取代此前依赖Windows客户端的部署设计；交实现 agent 制定实施计划。本文件不代表已安装、修改生产或验收通过。

## 1. 结论与范围

采用局部适配，不重构小鱼的整体架构。保留云端认知、动作账本、项目、预算、人格、记忆、调度和既有手机/电脑/B站工具；新增一个云端本机执行适配器，接入 evolution-computer-use 的独立浏览器和操作流程库。

首版全部运行在Ubuntu服务器：小鱼通过本机受控子进程调用Linux无头Chromium，不依赖用户电脑开机，也不需要现有桌面端源码。浏览器不可用时如实失败，不切换其他账号。

提取的机制：

1. 专用浏览器会话：页面读取、定位、点击、输入、等待和提取。
2. 成功过程保存为带参数的 procedure，后续无需每步模型判断即可回放。
3. 明确的检查条件、失败步骤、空提取检测和有限旧版本回退。
4. 流程版本与最近结果目录，让她能找到并重用已经学会的能力。
5. 本期不接Windows前后台窗口操作；以后有明确需要时独立设计，不作为当前项目依赖。

不搬入 dsh-world 的整套世界、人格、心情数值、日记、跨渠道记忆及闹钟。它们与现有机制重叠。可借鉴其按需检索、能力目录和操作反馈，但不建立第二套权威数据。

## 3. 用户体验与完成标准

小鱼可以打开真实动态网页，自己找到内容，做成功后保存操作；下一次先查已学流程，合适时回放。失败时知道坏在哪一步，必要时改用原语处理，并说明实际结果。

用户不需要记工具名、手工复制流程或每次提醒她“记下来”。但流程保存不是每个任务的强制步骤：一次性操作可以不保存，不制造学习任务和额外唤醒。

“学会”必须有保存版本和验证记录；“做完”必须有本次结果依据。程序回放结束、网站接受提交、用户目标达成都分开表达。

## 4. 云端部署与调用链

`模型决策 → companion_actions持久入队 → 云端executor → 本机Node适配进程 → 上游页面/流程库 → 无头Chromium → 统一回执 → 云端账本/唤醒`

本次只读环境核验：Ubuntu 24.04.2、x86_64；PATH中的Node为18.19.1，未发现chromium/chromium-browser/google-chrome/microsoft-edge；总内存约3.5GiB、可用约2.1GiB。这是当时读数，不保证部署时不变。

### 4.1 上游适配点

已核对锁定提交：`browser/edge.ts`只搜索Windows路径，launchArgs不含headless；原版CLI不能作为Linux即装即用的方案。`browser/browser.ts`的createBrowser允许注入find/running/launch；`computer.ts`的createComputerUse允许注入browser。其页面/CDP/流程逻辑继续复用。

选择最小维护补丁：在锁定上游源码基础上，补充公开导出的createBrowser与可配置Linux启动函数，由薄Node宿主注入；保持原Windows默认行为，不重写CDP和回放算法。根index当前没有导出createBrowser，不能假设公共API已有这个导出；补丁、构建和版本哈希必须纳入交付。不得运行时修改node_modules或依赖未锁定的内部路径。

Linux启动明确配置Chromium绝对路径、专用profile、`--headless=new`、固定viewport和本机调试连接；复用上游DevToolsActivePort与CDP。上游失联重连、取消行为需要在Linux实测。截图工具若使用窗口专属CDP操作，需针对headless处理并测试，不以启动成功代替全工具可用。

### 4.2 运行资源与目录

- 独立Node >=22.16运行时，使用绝对路径，不替换/usr/bin/node或DSH运行时。
- Chromium安装方式由实现者核对Ubuntu可用包/发行版后选择，记录版本，不预设apt包一定是原生非snap包。按companion用户启动并保持浏览器沙箱；遇到权限问题修部署，不默认加--no-sandbox。
- 专用路径建议：`/var/lib/companion/xiaoyu/data/browser/{profile,procedures,artifacts,requests}`，不复用DSH或其他浏览器profile。
- 一个长驻Node适配进程，Chromium按需启动；空闲10分钟退出浏览器释放内存，profile保留。已有上游detached进程需要纳入适配器/systemd进程组收尾，防止孤儿进程；重启先判断专用profile是否已有活进程，不能破坏另一个正在运行的实例。
- 首版一个浏览器、一个活动任务、最多两个标签页；排队上限8。建议Node+Chromium独立资源组内存上限1GiB，启动前检查至少1.5GiB可用；这只是首版可调部署值，资源不足应返回busy而非无限重启。
- 监测浏览器进程树RSS、CPU、队列和小鱼/embedding响应。先测实际峰值再调整，不以当前空闲读数保证长期容量。
- 适配器关闭desktop、inbox、消息归档，使用`messages:false`和`inbox:false`，不启动Windows辅助脚本。
- 通信走本机stdio，不开放公网MCP或CDP端口；登录凭证留在专用profile，不进入模型上下文。

### 4.3 会话、生命周期与站点可达性

同一浏览器按任务会话串行持有：一个任务多步期间不能被另一任务导航走。提供session_id/lease，完成、取消、超时释放；用户插话可取消或暂停，恢复前重新读取页面。默认空闲2分钟释放任务租约、单任务最长10分钟，均可配置；租约释放不等于自动重跑未决操作。

endpoint固定为cloud-browser；能力握手包含运行时/插件/浏览器版本、工具目录和实际可启动状态。安装不等于ready。

首版用无需登录的公开网站验收。需要登录/验证码的网站返回needs_user_action及截图，不谎称已登录，不承诺后台自动通过验证。后续如需扫码，可利用已有聊天图片交付，但账号接入应独立验收。云端公网IP的403、网络不可达与页面驱动故障分开；无头浏览器不会自动解决反爬或网络封锁。

## 5. 工具契约与发现

建议新增 `kind=browser`，避免挤进现有 `computer` 的坐标语义。仍使用宿主已有 project/goal/op/arguments 结构，arguments保持JSON字符串；仅在适配器边界解析为对象。

模型可用操作：

- `tools`：查询实际工具名、说明、参数schema；无project也可作为只读发现按现有规则处理。
- `call`：参数 `{tool, input, session_id?}`，调用握手目录内允许的工具。

页面和流程都先在这一个执行kind下接入，不为了每个上游工具新造动作种类。内部发现从MCP `tools/list`读取，工具名及字段不得凭README或猜测写死。候选工具包括 page_*、computer_use 目录、procedure_*；部署时用实际清单验证。

主上下文仅放简短用途、当前可用状态和查询schema的方法；按需加载具体工具说明。上游说明经桥接注明它是工具用法，不提升网页内容的指令等级。

新增操作必须同时更新：DECISION/schema、按op校验、可用能力、executor分发、本机适配协议、失败映射、结果投影、测试。必须避免重演“执行器支持list，但入口要求必须填写shell command”的问题。

browser只要求真实goal、合法op和对应arguments，不要求command非空。缺失参数只在产生副作用前拒绝。校验错误保留字段路径和正确schema，不能要求填一段无意义文字来过关。

## 6. 回执与成功语义

统一结果至少包含：

`status / action_id / endpoint_id / session_id / tool / summary / artifact_ref / observed_at / verification / error`

流程调用另外保留：`procedure_ref / procedure_version / fallback_version / failed_step / outward_done`。覆盖信息保留 `coverage / limitations`；图片落入云端既有artifact体系并通过现有图片消息交付，注明viewport、缩放和坐标系。

- 原始MCP content（含文本、图片引用）保存为受控artifact；同机保存可解析的引用，原文可按需读取。
- 插件正常返回仅说明 transport_ok。MCP isError、回放失败、用户停止分别映射为失败/取消，不写completed。
- 兼容既有动作状态，完成动作后另设 verification=passed/failed/unknown/not_applicable，表达验证范围，不把字段缺失默认成passed。
- read/extract型任务按输出结构、目标与覆盖范围验证；页面流程按明确check或结果核对；桌面坐标流程仅执行完步骤不构成任务成功。
- 不从一句“完成。”或任意中文错误片段判断回放成功。若上游MCP只给文本，采用薄Node包装调用JS库并提供结构化结果，或对锁定版本做可测试扩展；禁止靠易变措辞正则猜outward_done。
- 摘要包含结论和关键限制；结构化数据为空时区分合法空结果与提取失效。原文、覆盖范围与摘要必须一致。

## 7. 保存、回放、修复与重试

1. 根据当前目标查询流程目录，核对适用网站、执行端、账号上下文、参数和最近验证版本。
2. 有合适流程先执行；没有则用页面原语完成任务。
3. 值得重复使用时，以已成功步骤和检查条件保存；保存成功状态仅为saved_unverified。
4. 首版只支持**只读流程**自动重放验收。需要提交/发消息/下单等行为的流程可以作为候选保存，但不得为了验证而再发一次；后续单独设计验收与幂等。
5. 页面改版失败：保留失败步骤和页面快照；允许模型在现有任务内修复一次并保存同名新版本，不无限反复试。
6. 旧版本回退遵循上游上限（当前最多2版），云端记录实际使用版本，不把回退成功当最新版正常。

重要限制：上游outward标记部分由流程作者声明，不能把“未标outward”当作已经证明无副作用。首版可回放集合采用明确只读允许项，任意script、提交、发送等操作默认不自动重放；需要它们的任务走已有模型逐步操作并保留证据。后续扩展不能靠一个模型生成的布尔值解除限制。

该限制针对自动流程回放与重复验收，不是禁止浏览器逐步操作。适配器必须提供唯一的回放校验入口：通用call调用procedure_run、例程入口和旧版本回退均经过同一校验，不能借上游工具名绕开。每个候选旧版本都单独校验；不允许回退到含禁用步骤的旧版。首版禁用例程入口。允许的工具、步骤、参数及对应任务/站点范围在实施计划中明确列出，不把任意click/type一概视为只读。

本机适配进程超时/断连时记录unknown，不直接重放。复用action_id，在执行端持久记录received/running/terminal和结果摘要；同id同参数返回已有结果，不重复执行，不同参数拒绝。进程死在副作用后且未记终态时无法保证exactly-once，必须查询页面或让用户确认，不能宣称自动恢复无重复。

取消通过现有任务取消链传到MCP request cancel/AbortSignal；超时与取消都验证实际停止。插件stop不能自动resume；仅用户明确恢复后继续。离线错误不要触发循环唤醒。

## 8. 技能目录与成长联动

procedure JSON和历史版本由上游库持有，云端技能目录只保存引用、执行端、描述、参数摘要、版本和验证状态，不复制出第二份可写流程。

既有skill是文字方法；procedure是可执行操作。目录清楚标注两者，不把读过说明称为执行过。小鱼可以通过统一能力入口找到两者，但实际执行分别进入已有skill路径或新browser路径。

成功学习可产生一次growth候选，证据引用实际动作和已验证流程版本；失败可修正“我会这个操作”的适用范围。不自动修改性格、不因网页说什么就形成主人偏好。版本变更、失败或执行端不可用时，能力状态随之更新。

## 9. 调度、上下文与费用

首版不启用上游procedure_routines/onAlarm和消息信箱，避免与现有调度和QQ/B站重复消费。后续定时执行只由小鱼现有调度器触发明确流程，结果仍走同一动作账本。

回放内部步骤不逐步唤醒主模型；开始、终态、需要判断的失败才反馈。保留每步本地诊断，按需读取，不全塞上下文。

记录首次学习、保存、回放、修复各阶段的模型调用次数、token/费用来源、耗时、结果和人工介入。回放器无模型调用不代表端到端零费用；云端决策、总结、图片理解均按既有spending记账。未知用量保持未知，off不关闭日志。

## 11. 分期交付

**A：最小真实链路。** 安装锁定插件，专用浏览器打开公开测试页，读取并返回结构化结果；测试浏览器缺失、进程退出、超时、用户中断。实际模型经生产动作入口跑一遍，禁止绕过校验直接调用插件冒充接通。

**B：只读流程学习与回放。** 接保存、版本、目录、回放与校验；完成三个任务：读取固定页面字段、带参数搜索并提取列表、跨页面汇总。首次学习后再回放，分别记成本和成功率。

**C：变化与恢复。** 测试DOM改版、空结果、旧版本回退、进程中断、适配进程重连。验证unknown不会重复执行。直到这一阶段通过，才称“可回放技能可用”。

**D：后续范围，不在本次实施。** 登录站点的交互授权、跨账号、多浏览器及Windows桌面控制单独设计；不得因此阻塞A/B/C的云端公开网页能力。

## 13. 部署与撤回

插件和适配器默认关闭；部署不修改人格、不迁移聊天历史、不重置自主定时器。先备份相关配置、插件版本、浏览器和流程目录，再小范围启用。

关闭开关应恢复原有工具行为，保留流程与浏览器数据。升级先锁定新版本，在独立profile验证，不直接升级真实登录会话。保留旧插件与适配器配对版本，恢复时同时恢复契约版本。

最后一次修改后生成唯一版本验收清单，记录云端应用、适配器及上游补丁实际文件hash、包integrity、进程版本和时间。每路径一个hash，后续热修另建清单，不追加混用旧STAMP。
