# 小鱼浏览器与可回放技能接入设计

日期：2026-11-19（北京时间）

状态：交实现 agent 评审和制定实施计划；本文件不代表已安装、修改生产或验收通过。

## 1. 结论与范围

采用局部适配，不重构小鱼的整体架构。保留云端认知、动作账本、项目、预算、人格、记忆、调度和既有手机/电脑/B站工具；新增一个桌面端执行适配器，接入 evolution-computer-use 的独立浏览器和操作流程库。

首版在用户 Windows 电脑运行专用浏览器，云端经现有认证远程连接调用。电脑离线时如实不可用，不偷偷切换云端浏览器或另一账号。Linux 云端浏览器是后续独立部署选项，本期不做。

提取的机制：

1. 专用浏览器会话：页面读取、定位、点击、输入、等待和提取。
2. 成功过程保存为带参数的 procedure，后续无需每步模型判断即可回放。
3. 明确的检查条件、失败步骤、空提取检测和有限旧版本回退。
4. 流程版本与最近结果目录，让她能找到并重用已经学会的能力。
5. 第二阶段评估后台窗口操作，减少抢鼠标和焦点。

不搬入 dsh-world 的整套世界、人格、心情数值、日记、跨渠道记忆及闹钟。它们与现有机制重叠。可借鉴其按需检索、能力目录和操作反馈，但不建立第二套权威数据。

## 3. 用户体验与完成标准

小鱼可以打开真实动态网页，自己找到内容，做成功后保存操作；下一次先查已学流程，合适时回放。失败时知道坏在哪一步，必要时改用原语处理，并说明实际结果。

用户不需要记工具名、手工复制流程或每次提醒她“记下来”。但流程保存不是每个任务的强制步骤：一次性操作可以不保存，不制造学习任务和额外唤醒。

“学会”必须有保存版本和验证记录；“做完”必须有本次结果依据。程序回放结束、网站接受提交、用户目标达成都分开表达。

## 4. 部署与调用链

调用链：

`模型决策 → companion_actions持久入队 → 云端executor → 已认证桌面连接 → 桌面适配器 → 本机MCP stdio进程 → 专用浏览器 → 统一回执 → 云端账本/唤醒`

- 桌面端管理一个长驻插件进程，不每次工具调用重新 npx 启动。
- 使用已安装、锁版本的入口，传绝对 `--data/--profile/--procedures` 路径；三者落在小鱼自己的应用数据目录。
- 首版 `--desktop off --no-inbox --no-messages`，只启用专用浏览器。先验证这两个关闭参数确实阻止重复消息归档与通知入口。
- 不复用用户日常浏览器profile；用户登录后会话持久化。登录凭证留在实际执行机器，不进入云端提示词或回执。
- stdio由桌面进程持有，不在公网开放MCP端口；现有远程桥若不支持该调用，则增加专用请求类型，而非远程任意shell。
- 同一浏览器按任务会话串行持有：一个任务多步操作期间不能被另一任务导航走。提供session_id/lease，完成、取消、超时释放；用户插话可取消或暂停，暂停后恢复前重新读取页面。
- 租约只覆盖实际浏览器任务，不能无限占用。首版默认空闲2分钟、单任务最长10分钟，可配置；超时后禁止继续操作，等待显式恢复并重读页面。

桌面重连发送能力握手：endpoint_id、工具版本、支持操作、浏览器可启动状态、桌面模式、halted。云端能力目录展示准确原因；安装了包不等于ready。

## 5. 工具契约与发现

建议新增 `kind=browser`，避免挤进现有 `computer` 的坐标语义。仍使用宿主已有 project/goal/op/arguments 结构，arguments保持JSON字符串；仅在适配器边界解析为对象。

模型可用操作：

- `tools`：查询实际工具名、说明、参数schema；无project也可作为只读发现按现有规则处理。
- `call`：参数 `{tool, input, session_id?}`，调用握手目录内允许的工具。

页面和流程都先在这一个执行kind下接入，不为了每个上游工具新造动作种类。内部发现从MCP `tools/list`读取，工具名及字段不得凭README或猜测写死。候选工具包括 page_*、computer_use 目录、procedure_*；部署时用实际清单验证。

主上下文仅放简短用途、当前可用状态和查询schema的方法；按需加载具体工具说明。上游说明经桥接注明它是工具用法，不提升网页内容的指令等级。

新增操作必须同时更新：DECISION/schema、按op校验、可用能力、executor分发、远程协议、失败映射、结果投影、测试。必须避免重演“执行器支持list，但入口要求必须填写shell command”的问题。

browser只要求真实goal、合法op和对应arguments，不要求command非空。缺失参数只在产生副作用前拒绝。校验错误保留字段路径和正确schema，不能要求填一段无意义文字来过关。

## 6. 回执与成功语义

统一结果至少包含：

`status / action_id / endpoint_id / session_id / tool / summary / artifact_ref / observed_at / verification / error`

流程调用另外保留：`procedure_ref / procedure_version / fallback_version / failed_step / outward_done`。覆盖信息保留 `coverage / limitations`；图片使用现有媒体传输，注明坐标系，不能把Windows本地路径当云端可读路径。

- 原始MCP content（含文本、图片引用）保存为受控artifact；云端存可解析的引用，原文可按需读取。
- 插件正常返回仅说明 transport_ok。MCP isError、回放失败、用户停止分别映射为失败/取消，不写completed。
- 兼容既有动作状态，完成动作后另设 verification=passed/failed/unknown/not_applicable，表达验证范围，不把字段缺失默认成passed。
- read/extract型任务按输出结构、目标与覆盖范围验证；页面流程按明确check或结果核对；桌面坐标流程仅执行完步骤不构成任务成功。
- 不从一句“完成。”或任意中文错误片段判断回放成功。若上游MCP只给文本，采用薄Node包装调用JS库并提供结构化结果，或对锁定版本做可测试扩展；禁止靠易变措辞正则猜outward_done。
- 摘要包含结论和关键限制；结构化数据为空时区分合法空结果与提取失效。原文、覆盖范围与摘要必须一致。

## 7. 保存、回放、修复与重试

1. 根据当前目标查询流程目录，核对适用网站、执行端、账号上下文、参数和最近验证版本。
2. 有合适流程先执行；没有则用页面原语完成任务。
3. 值得重复使用时，以已成功步骤和检查条件保存；保存成功状态仅为saved_unverified。
4. 首版只支持**只读流程**自动重放验收。需要提交/发消息/下单等行为的流程可以作为候选保存，但不得为了验证而再发一次；后续单独设计验收与幂等。
5. 页面改版失败：保留失败步骤和页面快照；允许模型在现有任务内修复一次并保存同名新版本，不无限反复试。
6. 旧版本回退遵循上游上限（当前最多2版），云端记录实际使用版本，不把回退成功当最新版正常。

重要限制：上游outward标记部分由流程作者声明，不能把“未标outward”当作已经证明无副作用。首版可回放集合采用明确只读允许项，任意script、提交、发送等操作默认不自动重放；需要它们的任务走已有模型逐步操作并保留证据。后续扩展不能靠一个模型生成的布尔值解除限制。

该限制针对自动流程回放与重复验收，不是禁止浏览器逐步操作。适配器必须提供唯一的回放校验入口：通用call调用procedure_run、例程入口和旧版本回退均经过同一校验，不能借上游工具名绕开。每个候选旧版本都单独校验；不允许回退到含禁用步骤的旧版。首版禁用例程入口。允许的工具、步骤、参数及对应任务/站点范围在实施计划中明确列出，不把任意click/type一概视为只读。

桌面RPC超时/断连时记录unknown，不直接重放。复用action_id，在执行端持久记录received/running/terminal和结果摘要；同id同参数返回已有结果，不重复执行，不同参数拒绝。进程死在副作用后且未记终态时无法保证exactly-once，必须查询页面或让用户确认，不能宣称自动恢复无重复。

取消通过现有任务取消链传到MCP request cancel/AbortSignal；超时与取消都验证实际停止。插件stop不能自动resume；仅用户明确恢复后继续。离线错误不要触发循环唤醒。

## 8. 技能目录与成长联动

procedure JSON和历史版本由上游库持有，云端技能目录只保存引用、执行端、描述、参数摘要、版本和验证状态，不复制出第二份可写流程。

既有skill是文字方法；procedure是可执行操作。目录清楚标注两者，不把读过说明称为执行过。小鱼可以通过统一能力入口找到两者，但实际执行分别进入已有skill路径或新browser路径。

成功学习可产生一次growth候选，证据引用实际动作和已验证流程版本；失败可修正“我会这个操作”的适用范围。不自动修改性格、不因网页说什么就形成主人偏好。版本变更、失败或执行端不可用时，能力状态随之更新。

## 9. 调度、上下文与费用

首版不启用上游procedure_routines/onAlarm和消息信箱，避免与现有调度和QQ/B站重复消费。后续定时执行只由小鱼现有调度器触发明确流程，结果仍走同一动作账本。

回放内部步骤不逐步唤醒主模型；开始、终态、需要判断的失败才反馈。保留每步本地诊断，按需读取，不全塞上下文。

记录首次学习、保存、回放、修复各阶段的模型调用次数、token/费用来源、耗时、结果和人工介入。回放器无模型调用不代表端到端零费用；云端决策、总结、图片理解均按既有spending记账。未知用量保持未知，off不关闭日志。

## 10. 具体改动落点

实现前以最新云端/桌面版本为准，先记录基线和当前未合并变更。以下模块是职责定位，不要求照搬文件行号：

| 位置 | 修改 |
|---|---|
| companion决策schema、解码及校验 | 新增browser契约，按op验证，入队成功才允许“已派出” |
| companion_executor及能力投影 | 分发新kind、真实ready状态、按端点错误降级 |
| companion_remote与实际Windows客户端 | 专用browser请求、会话租约、取消、重连、action_id结果查询 |
| 新browser adapter | MCP生命周期、tools/list、schema校验、结构化结果适配 |
| 既有结果视图与artifact入口 | 成功/失败/覆盖/路径正确投影，可读取执行端原文 |
| 既有skill/growth目录 | 引用已验证流程，不复制权威数据 |
| 测试及部署清单 | 协议、离线、真机、版本与回滚证据 |

不改phone和现有computer坐标定义；浏览器DOM定位、窗口截图坐标、全屏截图坐标必须标明来源，不能相互套用。

## 11. 分期交付

**A：最小真实链路。** 安装锁定插件，专用浏览器打开公开测试页，读取并返回结构化结果；测试离线、超时、用户中断。实际模型经生产动作入口跑一遍，禁止绕过校验直接调用插件冒充接通。

**B：只读流程学习与回放。** 接保存、版本、目录、回放与校验；完成三个任务：读取固定页面字段、带参数搜索并提取列表、跨页面汇总。首次学习后再回放，分别记成本和成功率。

**C：变化与恢复。** 测试DOM改版、空结果、旧版本回退、进程中断、远程重连。验证unknown不会重复执行。直到这一阶段通过，才称“可回放技能可用”。

**D：可选桌面后台。** 独立开关background，测试至少两种实际应用及不同窗口尺寸；不自动替换现有computer。桌面回放缺少网页式check时，通过末尾截图和实际状态核验，不泛称通用后台控制。foreground与外发流程另行扩展。

## 12. 验收清单

| 场景 | 判据 |
|---|---|
| 工具发现 | 注册目录、模型说明、校验器和执行器的名称参数一致 |
| 自然语言委托 | 模型生成动作→入队→远端执行→账本→聊天结果全链可追溯 |
| 真实网页读取 | 返回目标内容及来源，不用假模型输出代替真实读页 |
| 连续两任务 | 第二任务不能导航破坏第一任务页面；取消可释放租约 |
| 保存流程 | 有版本与实际步骤依据；未验证不能显示已学会 |
| 相同流程三次回放 | 各次结果正确，模型调用与首次学习分开计 |
| 页面改版/空提取 | 明确失败步骤；合法空集合须有任务依据，不混为无新消息 |
| 旧版回退 | 标明运行版本，最新版仍标失效，副作用状态不明时不回退 |
| 网络断连/重复请求 | 同action_id不再次执行；不确定结果标unknown |
| 用户叫停 | 实际操作停止，重启不擅自恢复被停止流程 |
| 文件与图片 | 本地artifact可从云端受控读取，截图坐标与原图一致 |
| 能力不可用 | 不生成无休止重试，不伪称已运行 |
| 已有功能 | 手机、原computer、B站、记忆与日常聊天回归通过 |

模拟契约测试与真实浏览器测试分开报告。最终表格写明每个任务的首次学习/回放/修复费用、完成情况和失败原因；不能以一次成功或作者实验代替本项目验收。

## 13. 部署与撤回

插件和适配器默认关闭；部署不修改人格、不迁移聊天历史、不重置自主定时器。先备份相关配置、插件版本、浏览器和流程目录，再小范围启用。

关闭开关应恢复原有工具行为，保留流程与浏览器数据。升级先锁定新版本，在独立profile验证，不直接升级真实登录会话。保留旧插件与适配器配对版本，恢复时同时恢复契约版本。

最后一次修改后生成唯一版本验收清单，记录云端和桌面端实际文件hash、包integrity、进程版本和时间。每路径一个hash，后续热修另建清单，不追加混用旧STAMP。

交付物：源码差异、配置示例、锁定依赖、测试结果、三项真实任务证据、费用与调用对照、部署/恢复说明、仍未覆盖事项。不得提交登录profile、cookie、API密钥或私人页面原文。

## 14. 给实现 agent 的执行说明

优先完成A+B+C；D为后续可选，不在首轮扩大范围。先确认桌面协议和客户端进程所在代码，再列最小修改计划；遵循现有repo约束和测试方式，不创建新的通用Agent框架。

结构化回执若无法从锁版本MCP可靠取得，选择薄Node包装JS API并说明原因，这是允许的适配取舍；不要重写上游回放算法。协议字段命名和既有表映射留给实现阶段，行为与验收要求不可省略。
