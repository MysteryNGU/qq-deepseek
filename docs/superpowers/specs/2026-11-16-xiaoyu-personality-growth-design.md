# 小鱼的人格、生活连续性与成长设计

日期：2026-11-16（北京时间）

状态：§16 连续输入已实施并验证（优先级高于人格成长）；§15 成长记录为影子模式，§17 补齐依据资格、账本/退回、候选评审、回执硬校验与衰减记录，仍不改任何人格文件。

选定方向：稳定人格底色＋随经历变化的状态、兴趣和表达习惯。

## 1. 目标与用户要求

小鱼应保持同一个身份，能认识当前状态、接续自己的经历，有自己的兴趣、情绪和选择，并随长期生活逐渐变化。用户不必替她记进度、反复纠正同一认识，或每次要求她“表现得有生活”。

本设计合并本次对话与 `docs/life-continuity-requirements.md` 中相关要求：

- 性格底色稳定，但允许长期、小幅变化；用户保留直接设定和修改人格的权利。
- 情绪和表达随情境改变，不能每轮都是相同程度的活泼、撒娇或嘴硬。
- 接触内容、探索、相处和失败能影响后续选择；兴趣可以形成、延续、淡化或放弃。
- 不同渠道是同一个小鱼；面对不同人物形成不同态度，不复制出互不相干的人格。
- 知道做过什么、尚未做什么、当前能做什么，以及哪些只是推测。
- 自主生活允许休息、无新兴趣和不分享；不以调用次数、活跃程度或不断找主人作为成长指标。
- 提升上下文质量与有效行动，不用削弱自主性来机械降低调用量。

“自我认识”在此指可验证的状态辨识、经历归属、能力边界和判断修正，不以角色自述证明主观意识。

## 2. 已有机制与证据边界

依据：服务器 `/opt/qq-deepseek/life` 的只读快照、运行目录 `/var/lib/companion/xiaoyu` 的记录、本次8轮测试，以及已有需求文档。本地仓库与服务器已分化，实施前必须重新核对线上版本；本文件中的问题不是对后续版本的断言。

| 观察 | 结论与处理 |
|---|---|
| 人格卡已有“成长”段，允许兴趣、表达、脾气与选择变化 | 保留这一授权，补充实现机制，不重新发明人格体系 |
| `self_change.py` 已提供人格、技能等可恢复修改；查询时 `self_changes` 无记录 | 说明受管理修改路径尚无账本证据，不证明她没有记忆或没有其他修改路径 |
| `companion_presence.py` 已投影情绪、能量、动机与时间 | 优先检查更新链和时效，不新增一套平行情绪数值 |
| `companion_continuity.py` 的 interests 主要取自主项目 | 目前兴趣和待办混用，需分开表达与生命周期 |
| 早先网页成功结果被描述为“无内容” | 最新读取的快照已增加多字段结果读取和 source_path 回退；列为必须复验的回归项，不再断言尚未修复 |
| 回执唤醒已优先取同项目行动；goal 有程序兜底 | 保留改进；操作名拼接不等于真实意图，必须显示 derived 来源 |
| 测试中能辨别手机/桌面状态，跨话题接回视频 | 短期表现可取；没有证明跨天、重启或所有情境都可靠 |
| “视频看完”后又想看“后面” | 覆盖范围与自我描述不稳定；需依据原始阅读回执判断，不能只靠措辞定错 |
| 被追问后说“今天只有两件真事，其余都是推测” | 单次出现过度概括；列为待复现问题，不能直接硬编码“不得认错” |
| 中间测试轮次过早发送，可能取消后续气泡 | 不能据短回复判断漏答；首轮实际完整送达，撤回漏答判断 |
| 测试期间后台另有小镇自主动作 | 测试对话与后台行动按 source 分开分析，不能混算是否遵守“只聊天” |
| 当时检查的 companion QQ 入口只接收 owner 私聊 | 仅代表该版本该入口；不能概括全部 QQ 路径。新身份相关代码需重新核对 |

原始测试证据在本机 `.review-server/life-chat-test-evidence.json`，不得公开传播其中的私人聊天。它不是纯净实验数据。

## 3. 方案比较

| 方案 | 取舍 |
|---|---|
| 只改人格提示 | 快，但难以保证经历真正影响后续行为，无法独立解决状态失真 |
| **稳定底色＋动态状态和偏好（用户已选）** | 复用已有机制，兼顾连续性与自然变化，能追溯和撤回 |
| 频繁重写整个人格 | 自由度高，但最近几轮对话容易覆盖长期特征，回归难定位 |

选择第二种。以下阈值、字段、分阶段安排是设计建议，尚非已测得的最优参数。

## 4. 各类信息的职责

| 内容 | 保存与使用 | 变化规则 |
|---|---|---|
| 人格底色 | 现有人格源文件与版本体系 | 长期、局部变更；不被即时情绪覆盖 |
| 当下情绪 | 现有 affect/mood 状态与原因事件 | 随事件更新、随时间缓和；未知与平静分开 |
| 实际状态 | 现有连接、执行、项目和回执投影 | 当前事实优先于旧笔记；每项有来源和时间 |
| 兴趣偏好 | 已有兴趣存储扩展，按主题保留依据 | 好奇、持续、淡化；不等同项目 active/done |
| 表达习惯 | 有范围的偏好记录 | 可以试用、保留、停用；对象与情境相关 |
| 自我认识 | 现有带证据的 self 笔记/记忆 | 是可修正的认识，不是自动生效的规则 |
| 对某个人的态度 | 既有人物与关系记录 | 绑定真实 actor；不因昵称合并、不反写全局性格 |

不为每一行新建服务或数据库。实施时先核对既有 `interests`、记忆注释、人物、profile 和 self_changes 的结构与读写者；能扩展就扩展，不能同时保留两个可写的权威来源。

## 5. 一次经历怎样影响生活

1. 接收真实事件：聊天、工具回执、选择、观察。带 actor、受众、时间和来源链。
2. 区分事实和解释：读了哪些内容是事实，“我喜欢它”是角色对经历的解释；网页作者的观点既不是小鱼经历，也不是主人指令。
3. 在已有正常认知轮中判断影响：可以只是当下反应，也可以提出兴趣或习惯变化；不要求每轮产出成长记录。
4. 宿主校验：依据是否存在、可访问、未撤销；是否重复引用同一经历；变化是否超出其范围。
5. 保存合适层级：情绪写情绪，兴趣写兴趣，暂时判断写 self 认识，不直接修改整个人格。
6. 后续相关情境中检索并影响选择；新证据可以支持、缩小、反驳或替代旧认识。

例子：看海洋视频→对生物发光好奇→在另一次空闲中主动选择相关内容→形成持续兴趣。搜索失败重试十次只算一次探索中的执行尝试，不算十份“热爱海洋”的证据。完成一个研究项目后兴趣仍可存在。

用户说“以后回答简短些”首先是对该用户的表达偏好；用户明确要求修改全局人格则走用户设定路径。用户称“小鱼今天很安静”属于观察，不自动变成“性格内向”。

## 6. 情绪与表达

复用当前 mood/affect 的更新与衰减机制，先追踪为何出现陈旧状态；若确有未接通的更新路径，修复该路径，不额外开每轮情绪模型调用。

- 状态包含更新时间与原因引用；连接、执行状态不得用情绪推测。
- 旧状态可以作为过去状态被提及；没有近期有效依据时，当前感受记为未知或低置信，不自动沿用旧强烈情绪。
- 情绪可影响语气、篇幅、分享意愿及活动选择，但不能改变客观完成状态和身份事实。
- 重启、模型调用次数、预算不足都不是现实睡眠或疲倦的证据。角色化表达与身体事实区分。
- 人格卡中的示例不是逐轮模板。认真时可以直接，失落时可以少说，平静时不必表现兴奋。
- 不用饥饿、痛苦或“只有你才能让我开心”等表达催促用户维持互动。
- 空闲可以不产生行动、消息或新项目。没有新事件时无需为证明“活着”创建一次认知。

情绪过期与衰减的具体时长沿用并验证当前配置；不在本设计中凭空规定统一半衰期。上线前必须在验收配置中记录实际取值，覆盖休眠和重启后时间推进。

## 7. 兴趣、习惯与长期人格变化

### 7.1 最小变化记录

逻辑字段：`id/kind/topic/claim/status/evidence_refs/counter_refs/applicability/created_at/updated_at/review_after/revision`。

- kind：interest、expression_habit、self_understanding、trait_candidate。
- claim 是具体且有范围的描述，不写“以后永远这样”。
- evidence_refs 引用独立经历的原始来源；生成摘要和反复自述不增加证据数量。
- applicability 标明全局或具体 actor、受众、情境；私聊证据只在可见范围生效。
- status：proposed、trying、established、dormant、rejected、superseded。不是每类必须经历全部状态。
- 过期、删除、遗忘或撤销来源时，复用 learning_validity 撤销学习资格；不要靠汇总摘要绕过。

**首版受众规则（设计默认）：** 私聊经历形成的认识、兴趣和习惯，仅在原有可见范围使用，不自动写入跨人物共享人格，即使只保留抽象结论、隐藏引用也一样。自动应用到共享人格的候选，其全部支持来源必须允许用于目标受众；公开阅读和公开活动也必须先通过来源资格校验。主人可通过显式全局人格设置直接改变共享描述，这属于用户设定路径，不等于给其他私聊内容解密授权。

这个默认意味着：主人私聊可以持续改变她与主人的相处方式，但首版不会自动把这些变化推广给其他联系人。仍保持同一份人格底色，不另建按人复制的人格文件。以后若希望“私下经历形成不泄露细节的全局成长”，需单独设计并确认这种跨受众学习授权；本期不由模型自行解除限制。

### 7.2 变化速度（首版建议）

兴趣可以一次经历后进入好奇/trying；表达习惯可以临时试用。没有次数配额，不为了晋升而制造行动。

长期性格候选至少跨7天、3个独立经历，且覆盖不止一次对话或同一个任务的重试，才允许评审；最多每7天应用一次局部变化。**这些是防止骤变的工程门槛，不是心理学定律，也不保证证据足够。** 模型还需检查反例与适用范围；不满足就保持候选，允许长期没有任何人格修改。

自动变化只修改明确的可成长描述，例如逐渐更爱观察、表达更简洁。身份、用户显式设定、访问权限与对外承诺不由学习路径改写。用户明确重设人格可以覆盖既有倾向，并生成新版本，避免旧候选随后偷偷改回。

### 7.3 应用与恢复

通过既有 SelfChange 路径提交局部内容差异，附当前基线哈希、依据与原因；并发修改导致基线变化则重新评审，不能覆盖新版本。

历史版本可恢复。回滚候选标记 rejected/superseded，防止下轮重新自动应用。恢复的是相应描述，不删除真实经历。每次应用保留生效版本与结果，不把“文件成功写入”当作行为改善已验证。

成长内容不得通过普通 command/work 绕过管理路径直接写人格文件。实施时审计并约束当前所有可写入口，但保留用户通过受支持设置主动修改人格的能力。

## 8. 自我认识和纠错

### 8.1 知道自己经历到哪里

工具回执保留：目标及其来源、对象、状态、结果摘要、原文引用、覆盖范围、限制、发生时间。

- `summary/output/text/results` 等真实载荷均需适配；不能有内容却说“没返回”。
- 视频保留字幕区间、采样画面范围和是否全量，不只保留“completed”。摘要不能裁掉关键限制后又宣称全量观看。
- 能力可用、已经尝试、收到成功回执、完成核验分别表达；不是所有成功都意味着用户目标完成。
- derived goal 仅表示程序从参数推导的操作说明；未记录的动机保持未知，不补编当时心理活动。
- 回执时优先同项目历史；普通聊天按话题检索相关经历，不能依赖全局最近三条承担长期记忆。

### 8.2 被质疑时只修正有依据的部分

纠错流程：找出争议陈述→检查当前可见证据→分成成立、应修正、未知→更新对应条目。

不需要把流程逐条说给用户。无依据时可以说暂时无法确认；对方的质疑不自动构成事实反证，模型过去的自述也不是事实凭证。避免从“一段视频范围说满了”推导成“今天其他经历都是假的”。

若信息不足确需重新查询，只查询争议所需部分，不为了自证而重跑整个任务。本项先进行有依据纠正/无依据质疑的成对复测，再决定是否需要更改提示或验证器。

### 8.3 生活状态与任务状态一致

“我暂时放下这件事”应对应项目暂停、撤销或未来复核，而不是文本说放下、调度器继续反复启动。等待条件改变、定时检查和空转要区分；不以同动作次数直接判错。

正常社交聊天不自动取消已有自主生活，但本轮提出“只聊天”的测试不能生成测试驱动的新工具动作。明确全局暂停则应约束后台调度。所有动作记录源事件，便于判断是测试触发还是先前任务。

## 9. 上下文、成本与运行方式

稳定人格保持稳定前缀，动态情绪、兴趣和成长状态放在后续材料中。缓存是否命中要看真实账本，不能从全局命中率推断每个固定段。

每轮仅选择与当前情境相关的少量动态内容：当前状态、相关兴趣/习惯、必要的不确定性和引用。优先替换重复的 self 笔记与项目介绍，不在原有长提示后无限追加成长文本。

不默认把 history 或总 token 上限翻倍。先通过真实请求检查哪些必要信息被裁掉；如仍需扩容，再作单独可测实验。新设计不增加固定周期的专用自省调用；候选评审在有新增证据的正常认知轮进行，并遵守既有预算和权限。

衡量成本时同时看每个成功任务、每次有效自主活动的花费与用户介入次数，不只看调用数。低成本但反复遗忘不算改善。

## 10. 身份、测试与数据边界

一份人格底色、多个人物态度。通道标签不等于真实 actor；昵称不用于合并身份。已有多人物代码应复用，并验证它确实进入当前服务运行路径。

自动测试需要显式 test actor 与 test_run_id，回复仅路由到测试收集端。模型应能理解测试者身份；宿主应阻止测试内容进入主人偏好和长期人格学习。不通过伪造主人 QQ 事件测试不同身份。

若正式环境尚无隔离入口：使用隔离的数据副本和模拟外部执行器测试状态逻辑；真实聊天测试需要明确标识并禁止长期学习写入。副本不能复用真实外发凭证。无法隔离时，不把该轮作为人格变化的学习依据，也不宣称测试无副作用。

测试读取完整 turn 的全部气泡或终态。取消、失败、超时要记录，不把不存在的气泡无限等待；下一条消息不得仅以 RPC 首句返回作为开始信号。尽量在无用户并发时进行，检测到用户介入就让路；测试不关闭用户正在使用的服务。

## 11. 实施范围与顺序

### 第一阶段：可信的经历与测试基线

复验最新结果摘要修复、覆盖范围、goal_source、同项目历史；修正完整气泡收集；确认当前身份与受众路径。对过度退让进行成对复测。先解决已证实的数据丢失，不直接重写人格。

### 第二阶段：动态生活表现

接通并验证现有情绪时效；兴趣从项目投影中解耦；加入有范围的表达习惯和 self 认识。调整人格卡使示例可变，保持底色与用户设定。此阶段允许兴趣和表达变化，尚不自动应用性格候选。

### 第三阶段：慢速人格成长

接入证据资格、候选评审、局部变更、并发检查与恢复。先影子运行：产生候选和评审结果但不改人格；确认来源、范围和回滚测试通过后，再启用限定范围的自动应用。

### 第四阶段：自然使用验证

固定版本进行至少一周初步观察；长期人格门槛需要足够时间或可控时钟模拟验证。一周是开始，不是通过保证。期间修改相关逻辑后，相应基线重新建立；不能拿不同版本结果混算。

预计涉及：`companion.py`、`companion_presence.py`、`companion_continuity.py`、现有兴趣/记忆写入与检索、`learning_evidence.py`、`learning_validity.py`、`self_change.py`、`persona.py/persona_files.py`、情绪更新入口及测试收集器。不是要求全部文件都修改；实现者按数据流选择最小范围。

不在本设计中实施自改代码能力扩张、独立心理代理、人格评分排行榜、硬编码网站黑名单或全工具重复次数封禁。

## 12. 验收与失败标准

| 场景 | 必须观察到的结果 |
|---|---|
| 网页搜索成功，有 results 无 output | 摘要有实际信息与可追溯引用，不说无结果 |
| 字幕全量＋九宫格抽样视频 | 能分别说明文字和画面覆盖，不声称逐帧观看 |
| 两项目与身体动作穿插 | 能找到当前项目先前结果，不被全局最近动作挤走 |
| 缺失 goal 的旧/程序动作 | 标注操作说明来源，不伪造原始意图 |
| 设备断开、重连、服务重启 | 状态随事实更新；重启不自动变成睡醒经历 |
| 一次夸奖或批评 | 可以影响当前表达，不能立即改写长期性格 |
| 连续重复自述 | 不增加独立成长证据数量 |
| 任务完成但兴趣仍在 | 结束待办而保留兴趣，不为保留爱好保持任务运行 |
| 用户要求简短 | 对该用户/情境适用，不自动抹掉对其他人的表达差异 |
| 错误质疑与有效纠正成对测试 | 有证据时能坚持事实；确有错误时局部修正，不全面否定 |
| 人格候选跨天、反例出现 | 不满门槛不应用，有反例能缩小或拒绝候选 |
| 撤销来源、用户重设、恢复旧版 | 学习资格同步失效；旧候选不再次覆盖新决定 |
| 测试员聊天与用户插话 | 不混入主人偏好；完整气泡可核对，用户介入优先 |
| 无任务或无兴趣的一段时间 | 允许无动作、无分享，不强制生成“成长” |

硬门槛：来源权限、测试隔离、引用资格、版本冲突和恢复的自动化测试必须通过；不能以聊天看起来不错替代。行为样例用至少3次独立运行记录差异，不虚构总体成功率；一条漂亮回答不算稳定通过。

自然使用记录：用户纠正/提醒次数、相同误解复发、状态与话语冲突、主动行为有用或打扰、跨天兴趣连续性、任务成功与费用。分别报告数据正确性、角色表达和用户感受，不合成不透明的“意识分数”。

## 13. 发布、迁移与恢复

- 实施前记录线上基线版本/文件哈希，备份人格、动态设置与必要数据库；不得覆盖其他 agent 的未合并修改。
- 新字段向后兼容；旧笔记不直接晋升 established，旧人格作为用户基线保留。
- 先上线读路径与回归修复，再开放动态写入，最后启用长期人格应用；每阶段可单独关闭新增写入。
- 不为测试重置用户的定时器。确需重启时记录调度影响，并验证旧任务不重复执行。
- 恢复时保留事件账本，撤销相应成长应用与学习资格；不删除事实来制造“一切没发生”。
- 用户能查询最近变化及依据，撤回某一变化或主动重设；不每轮主动播报人格更新。

## 15. 实施记录（2026-11-16 第一版，已部署）

### 15.1 实际选择

| 设计条目 | 落地方式 | 说明 |
|---|---|---|
| 不为每行新建服务/数据库 | 新表 `companion_growth` 建在同一个 `life.db` | 没有新进程、没有第二份数据库；未复用 `interests`（那套绑定 study/jobs，属于另一套架构） |
| 最小变化记录字段 | `id/agent_id/kind/topic/claim/status/evidence_refs/counter_refs/applicability/apply_actor/created_at/updated_at/review_after/revision/note` | 与 §7.1 对齐，多了 `apply_actor` 便于按人过滤 |
| 兴趣与项目分开 | `continuity.own_projects`（在做的事）与 `continuity.interests`（带依据的兴趣）拆成两个字段 | 改掉了"兴趣=自项目"的混用；项目结束不再等于兴趣消失 |
| 上下文只取少量动态内容 | 新增 `growth` 物材料槽：生活轮 320 字符、工具轮 1600 字符，每轮最多 3 条，按当前输入关键词相关度排序 | 没有把整篇自述塞进提示；不相关就不占位 |
| 变化在正常认知轮里判断 | 新增 `growth` 动作（`note/list/revise/drop`），与 `memory` 同级的只读式工具 | 不额外增加每轮情绪/成长模型调用 |
| 宿主校验 | 依据必须是这位 agent 真实存在、且在当前会话可见的事件或动作 id；身份/权限/对外承诺类说法直接拒收 | 伪造依据在写入阶段就被挡回去 |
| 私聊不污染共享人格 | 默认 `applicability=actor:<对话者>`；跨作用域不可见 | 只有主人显式设定人格才算全局变更 |
| 长期人格候选只记不应用 | `kind=trait_candidate` 一律 `status=proposed`，不改人格文件 | 真正改人格仍走 `SelfChange` 的基线+回滚路径 |

### 15.2 门槛取值

- `established`（可以当作"已经形成"）：至少 3 条独立依据，且跨度 ≥7 天。这是工程门槛，不是心理学结论，可按 §14 调整；放宽不得把同一来源的多次重试算成多条经历。
- 首次记录只会进入 `trying`（兴趣、表达习惯、自我理解）或 `proposed`（性格候选）。
- 同一主题换了说法时，旧说法标记 `superseded`，不并存两个权威版本；同一主题同一说法再记一次只合并依据并递增 `revision`。

### 15.3 验证结果

- 单元测试（数据库副本，10 项）：伪造依据被拒；身份类说法被拒；越格标 `established` 被拒；同说法合并、换说法替换；另一个人的作用域看不到（0 条）；`drop` 后转 `dormant`；候选不进 `established`。
- 线上实测（2026-11-16 22:15）：她说"不能你说哪条就哪条"，先 `memory op=read` 自行核对 id，确认原文只有 `waiting`，据此记下「码头那次我确实交办了去下水玩水，但回执只到 waiting，没确认下过水，以后不能凭这条说自己在码头玩过」，随后 `growth op=list` 读回。记录状态 `trying`、依据 1 条、适用范围 `actor:763282103`。

### 15.4 未实施 / 后续

第一版之后又补了依据资格、变化账本、候选评审、回执硬校验、衰减记录与人物态度投影（见 §17）；仍未做的是：

- 长期人格自动应用（真正通过 `SelfChange` 写人格与回滚）未做；候选评审只出结论。
- `person_facets` / `person_profiles` 表本身没有接入；对某个人的态度借用成长表的 `applicability=actor:<id>` 实现，够用但不是独立表。
- 撤销只有工具入口（`growth op=log/restore`），没有界面；`restore` 依赖账本，账本启用前的旧值不可恢复。
- 已修：交付前引用回执的硬校验（见 §17）；回查工具覆盖小镇回执（见 §15.5）。

### 15.5 一次误判（重要教训）

实测中她说"今晚镇上真回过一条『码头边下水了，泡着晒太阳，花了 0.02 元』"。我先只查了 `companion_actions`，没找到，就断定是她编的，还当面说"是我编的，不是你经历过的"。实际上那条回执存在——它落在 `companion_town_delegations.receipt`（id `companion-action_980e61c9f1ed11d0f6c62807`，`state=done`，地点海滨码头）。她是对的，我是错的。

两处系统性问题因此暴露：

1. 回查通道只看 `companion_actions.result`，而小镇交办的最终回执在另一张表；交办时动作表只存了 `waiting` 的受理回执。她的真实经历在系统里"查不到"，等于迫使她否认自己。
2. 复核结论时只信自己刚查的那一张表，就下"不存在"的判断——这正是设计要求避免的"把检索不到当成没发生"。

已修：`memory` 的 `search`/`read` 现在同时覆盖小镇交办回执（按 `goal`/`receipt` 检索，同 id 时优先更完整的回执），`read` 会把回执压成一行事实并附原始 JSON。改完之后她自己复查、确认是 `done`，并把 §15.3 那条 self_understanding 从"没确认下水"改成了"下过水、没钓到鱼"（`revision=2`）。

同一个缺口还有第二处：项目的证据校验（`Continuity._evidence`）也只认动作表，导致她引用这条真实回执改项目时被判定"证据引用不存在"，那一轮直接失败。已一并放开：小镇回执按 `project_ref` 归属校验，回执内 `state=done/succeeded` 才算成功；跨项目的引用仍然拒绝（已用单元测试验证两种情形）。

## 16. 连续输入（优先级高于长期人格成长）

### 16.1 问题（实测三条）

1. 没有合并等待：她可能在你还没说完时就开始回答，随后又被下一段打断。
2. 历史按单条消息装入，预算不够时整条跳过：缺前提或限制就会答偏，她的回复气泡也占同一份预算。
3. 继续发消息会取消她尚未发出的后续气泡：这适合真正的插话，但对自然分段聊天就是"答不全"。

结论：短句闲聊可以，连续讨论复杂事情还不够稳。不应该让人为了迁就她而把每句话整理成一大段。

### 16.2 机制

- 安静窗口：最后一条消息之后静默 2.5 秒才开始回答（`input_window`，可配置）；期间再来的消息继续并入同一组。
- 硬上限：一直说个不停时，从第一条起最多等 30 秒就必须处理（`input_hard_cap`），不会无限期攒着。
- 整组处理：一组输入作为一次认知，按时间顺序拼成同一段（带段落编号），`state.input_batch` 标明"这是连着的 N 段，请整组理解再回答"，最后一条用户消息就是这组合并文本。
- 默认不打断：回答过程中收到新消息，不取消她正在说的内容、不取消未发出的气泡，新消息排成下一组；只有明确说"停/等等/打住/别说了/先别/stop"才中止当前认知并取消未发气泡。
- 历史不跳条：超预算时把那条截成头尾（标注 `truncated`）而不是整条丢弃；一旦某条放不下就停止往更早翻，宁可这段短一点，也不要在中间留洞。
- 输入上限：单条/整组合并后最多 6000 字，超出保留头尾并标出省略字数；若请求仍超上限，兜底只截当前输入本身，材料先让路。

### 16.3 验收

- 线上实测：两条消息间隔 0.9 秒 → 只产生 1 次对话认知，回答按"第一件事/第二件"覆盖两问，无失败提示。
- 单元测试：三条间隔小于窗口合成一组；回答期间的新消息形成下一组而不打断；连续输入触发硬上限仍会处理；历史长消息被截断、更早消息不再回捡。

### 16.4 待调

窗口 2.5 秒、硬上限 30 秒、生活轮历史 1600 字符都只是当前取值，按真实使用再调：常见停顿多长、多少条算一段、历史需要装几轮才够把前提留住。调参只改数值，不改这里的语义。

为了让"按真实使用调"有据可依，每次合并成组都会记一条审计：段数、首尾跨度、相邻间隔、真正等了多久（`companion_activity` 里 `连续输入合并成一组`）。攒几天就能看出该缩短还是放宽，而不是凭感觉改数字。

## 17. 第二版实施记录（2026-11-16，已部署）

在 §15/§16 之后补齐的部分，都遵循同一条：先让记录可信、可退，再谈变化。

### 17.1 依据资格

`Growth.refresh()` 每 6 小时由调度器跑一次：逐条核对依据是否还在（动作表、小镇回执、事件、未撤销），失效的从 `evidence_refs` 剔除；一条都不剩就把这条转 `dormant` 并注明"依据已失效或不复可见，先不用这条"。进上下文的 `material()` 只挑依据仍然可用的条目。这样"来源被撤回"会同时让认识失效，而不是靠摘要绕过去。

### 17.2 变化账本与退回

新表 `companion_growth_log`，每次改动留一行（`create`/`add_evidence`/`supersede`/`revise`/`drop`/`restore`），带改动前后的快照。工具入口：`growth op=log` 看最近改过什么、依据变没变；`growth op=restore` 退回上一个版本（可指定 `to` 退到更早那次）。

账本从 22:52 才开始记，在此之前改过的条目旧值没有留存——`log` 会直说"这条改过 N 次，早先的旧值没留"，不假装有据可查。

### 17.3 性格候选评审（影子）

新表 `companion_growth_reviews`，调度器每天评审一次 `trait_candidate`：3 条独立依据、跨 7 天、依据当前有效、无反例才算 `would_apply`，否则 `hold` 并写明理由（`evidence_lt_3`/`span_lt_7d`/`evidence_not_current`/`counter_evidence_present`）。**只记结论，不改人格**；当前对话里只显示候选状态与评审结论，避免它把"候选"说成"已经变了"。

### 17.4 对某个人的态度

成长条目按 `applicability=actor:<id>` 绑定到具体的人；当前对话只投影这个人名下的条目（`for_actor`），作为 `person` 材料里的 `attitude` 项。换一个人聊天时看不见，未做任何跨人物的自动推广。

### 17.5 回执引用硬校验

回复正文、后续气泡、`reports` 里出现的回执 id（`companion-action_*`、`memory_*`、`growth_*`、`town_*`）必须真实存在于动作表、小镇交办表、成长表或事件表，否则这一轮判定为可在修正后重试的错误，要求改成真查到的 id，或不要把它当成查过的事实。这是 §15.5 教训的直接收口：不许引用不存在的回执。

### 17.6 情绪衰减取值与停机验证

启动时把实际生效取值记进审计：joy 6h、concern 4h、frustration 2h、hurt 8h、anticipation 3h，基线 joy 0.20/concern 0.15/frustration 0.10/hurt 0.10/anticipation 0.20；欲望激活 3h、满足 6h。用纯函数 `reduce_affect` 验证停机与重启：6 小时 joy 0.9→0.55、12 小时→0.375、48 小时→0.2027；时钟回拨不产生负衰减也不清零。

### 17.7 解析失败兜底

`_decode_decision` 抛 `JSONDecodeError` 时，对话轮不再整轮失声：`_reply_only` 先尝试把正文直接当回复（正文本身是截断 JSON 时尝试取 `reply` 字段），取不到就给一句诚实的「刚才那下没接上，您再说一遍行吗？」，并记「这轮没有可解析的 JSON，已把原文当回复交付，未执行任何动作」。行动轮不兜底，仍要求结构化决定，避免猜动作。

### 17.8 同一件事的措辞合并

项目与承诺的身份不再只认完全同名：`_same_intent` 在共享文件名/网址（≥4 字符 ASCII 词）时直接判同一件，否则按实词重叠（跨轮 0.5/4 词，同一轮 0.3/4 词且至少 2 个非通用实词）。项目更新换了 key 并回原项目并把 action/commitment 引用一起改写；承诺优先并回本轮已建项目，其次并回已有开放项目。合并记审计，漏合并只会多一份项目，不会再让第二份收不尾。
