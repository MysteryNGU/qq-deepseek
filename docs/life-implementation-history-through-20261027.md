### R1 · P1：旧学习清理边界误禁读原始历史经历

位置：`life/life_catalog.py:157–161`，经 `life/life_access.py` 同时影响召回及原文读取。

`live()` 对所有资源应用 `memory_policy_floor`，把清理时间线之前的原始 event 也判为不可用。该边界原本用于阻止已清理的叮嘱/推断重新成为当前结论，原始交流、工具证据和未知操作历史仍须可按需核对，见 README 的“记忆边界”说明。

隔离复现：保存一条普通用户交流，将该 scope 的 floor 设为其接收时间之后。数据库正文仍在、`redacted_at` 为空；新版原文读取返回 `not_available`，关键词召回为空。生产只读统计中，**10,585 条未删除事件**的接收时间早于对应 floor，落入同一拒读条件。该数字不是物理删除数量，也未逐条检查内容。

修复要求：将历史可读性与“能否作为当前学习依据”分开。合法原始经历仍可查，已撤销的叮嘱/推断不能因恢复历史读取而复活；明确遗忘、正文删除、来源失效及用途 deny 仍须生效。验收至少同时覆盖“旧原话可读”和“旧结论不能重新自动采用”。

### R2 · P1：新摘要可以绕过已撤销学习来源的屏障

位置：`life/memory_organize.py:121–145`、`life/memory_policy.py:66–75`。

整理提交把所有摘要存为 `kind='episode'`。即使包含 interpreted/hypothetical claim，也只设 `source_kind='inference'` 和从当前时间起算的有效期；`interpretation_current()` 对非 interpretation 直接放行。整理准备、读取与提交没有补上 `learning_source_barriers`、原推断期限等学习有效性校验。

隔离复现：创建一条 inference/reflection 原事件，登记撤销其学习资格的 barrier；通过内部整理读完后提交基于该事件的 interpreted claim。提交仍显示 `complete_for_range=true`，新摘要随后可以作为当前召回结果返回。生产存在 11 条 barrier，仅说明该机制并非空置；本次没有证明生产已经发生这类复活。

修复要求：历史上“曾这样想过”可作为带时间和状态的历史记录保留，但不能重新获得当前结论资格。按 claim 追踪原来源的撤销状态、推断期限及适用任务/媒体版本，适配统一来源范围；不能仅将整个摘要改成 interpretation 后照搬原单 scope 校验，也不能一律从摘要生成时续期。验收包括已撤销来源、过期推断、多来源混合摘要及重复整理不续期。

### R3 · P1：单条内部禁用来源可阻塞全部后续小时整理，状态仍显示 ready

位置：`life/memory_worker.py:321–339`。

选批只检查 `catalog.live()`，没有按 internal_use 资格划分来源。遇到一条 live 但禁止内部使用的事件，`prepare()` 抛出 `not_available`；窗口已保存但没有 job，游标不推进，下次再次取到同一条。另一个相关分支是整批 refs 为空时直接返回，同样不推进。

隔离复现：第一条事件设置 internal_use deny，后面添加合法新事件，连续执行两次 tick。两次均为 `not_available`，内部派发次数为零；状态却仍为 ready、window_active=true、job_status/reason 为空。因此不能仅用健康状态证明整理持续前进。

修复要求：在覆盖清单中持久区分可整理、已删除、按用途禁用及待修复的来源，安全推进已扫描范围，不读取禁用正文、不假称已总结该来源。真正错误须显示原因与积压；真正 unknown 继续对账，不能为了推进而盲重发。验收应包含一条禁用来源后仍能处理合法来源、整批不可用、重启后不反复卡在同批。

### R4 · P2：位于片段之后的明确保密要求未被宿主检查覆盖

位置：`life/sharing_policy.py:60–73`。

### R7 · P2：外部计算跨北京时间午夜结算时，费用仍留在前一日
