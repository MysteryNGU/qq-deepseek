# 独立伙伴的 B 站入口

2026-11-15：独立 Companion 已接入 MCP 后端、字幕阅读、九宫格素材、独立视觉阅读和增量社交收件箱，不需要启动 DSH。工具目录按需读取，不把完整工具 schema 常驻普通聊天上下文。

已部署云端并真实验证：会话认证、搜索、回复/@/私信收件、视频取流、字幕摘要、九宫格视觉报告与单帧放大均已跑通。收件状态为 online；首次同步的19条历史记录只建立基线，没有拿历史消息试发回复。旧后端扫码写入空凭据却误报成功的问题已经修复，现有扫码会话已恢复，无需重新扫码。

## 账号怎么提供

无需提供账号密码或粘贴 Cookie 到聊天。使用连接设置中的 B 站登录入口，生成二维码后用 B 站 App 扫码，在手机确认登录；窗口持续检查同一登录会话。远端模式使用云端同一后端，凭据写入云端人物目录 `data/companion/bilibili/bili_credential.json`，不进入对话。应以非空有效凭据及真实 `bili_check_credential` 结果确认完成。关闭窗口前完成扫码；后端退出后尚未完成的二维码会话不能恢复，重新生成即可。

本地设置接口为 `inspect_status(cfg, home)`（仅文件存在状态，不代表有效登录），异步真实检查为同一 `Bilibili` 实例的 `call('bili_check_credential', {})`。扫码使用 `bili_login` 和 `bili_login_check`，结果的 `content[].text` 是JSON；二维码在 `qrcode_image` 中。新登录适配器保留 Set-Cookie / 跨域交换结果，真实 nav 鉴权通过后才原子保存。登录会话需保持该实例直到成功或取消。详见 `companion-bilibili-login.md`。

## 角色使用

动作 `kind:"bilibili"`，`op` 为工具名，`arguments` 为 JSON 对象字符串，`project` 为任务标签。先用 `op:"tools"` 列简短目录，再用 `arguments:'{"name":"bili_watch"}'` 查完整参数。搜索、详情、评论等仍走现有只读 MCP 工具；看视频用独立阅读入口：

```json
{"kind":"bilibili","project":"本次视频阅读","op":"bili_watch","arguments":"{\"bvid\":\"BV1234567890\",\"focus\":\"本次想了解的问题\",\"visual\":true,\"comments\":true}"}
```

BV 号仅为参数示例。`visual` 默认 `true`，`frame_time` 可指定秒数放大一张原尺寸画面，`start_char` 用于续读长字幕。兼容入口 `bili_subtitle` 也经过阅读层，默认只读字幕，不把全文直接灌回主角色。

## 字幕、画面与缓存

- 字幕阅读使用独立小上下文，不继承主人私聊和角色人格。每段最多 12000 字，一次最多 8 段；长字幕分段摘要后合成短报告。超过本次范围会返回 `coverage` 和 `next_start_char`，不会截断后声称读完。
- 九宫格复用 `dsh-bili-whale` 的 MIT 抽帧 CLI：取视频流并保存 mp4，以均匀时间点为骨架、吸附附近场景变化点，默认 3×3、每格宽 720 像素。时间点写入 manifest；字幕带默认不额外生成。按需单帧放大复用已下载视频。
- 视觉阶段单独调用支持 `image_url` 的模型，输入一张九宫格或单帧，以及短字幕摘要和真实时间点；不会再次输入字幕全文。画面与字幕证据分别标注，最终短报告给主角色使用，避免主聊天重复读取图片。
- 字幕摘要按 BV、内容、稳定元信息、关注点和范围缓存；评论点赞数与评论变化不会使字幕重读。评论另取少量样本：请求最多 6 条，主报告展示最多 3 条、每条 80 字，并保留独立证据路径。
- 画面缓存按 BV、分 P、采样参数保留 manifest、mp4 和拼图；文件齐全直接复用，缺拼图但视频仍在则本地重抽。视觉报告另外按实际图片 SHA256、模型、关注点和字幕摘要缓存。所有实际阅读模型调用进入费用账本；取消后保留已完成的分段缓存，未返回用量的调用记为未知。

原始资料与报告在人物 `data/companion/artifacts/bilibili-reader/`；视频、拼图、单帧与 manifest 在 `data/companion/artifacts/bilibili-frames/`。结果中的 `source_path`、`output_path`、`receipt_ref` 可追溯资料与报告；新评论采样有单独来源，缓存报告不冒充本轮重新阅读。

**阅读范围必须如实表达。** 现有字幕后端只取首分 P；主阅读入口的画面也默认首分 P。九宫格是稀疏抽样，不等于逐帧看完；字幕带也是抽样，不是完整 OCR。没有字幕但有画面时可以描述实际采样画面，不能猜测未验证的声音内容。取流或视觉接口失败会明确标记画面缺口，只返回已取得的字幕结果。当前取流复用插件的 `durl` 路径，不能保证覆盖所有仅有 DASH 或需要额外权限的视频。

## 社交生活与静默处理

收件箱读取回复、@ 和私信，按账号及来源持久去重。首次实际读到的历史只建立基线；默认约 120 秒轮询，没有新消息不调用模型，失败按现有退避处理。第三方材料保存在独立 `bilibili:social` 范围，不冒充主人私聊。

新消息进入同一个核心的正常认知与行动队列。后台 B 站活动默认内部处理，不逐条给主人发汇报；只有角色明确选择 `share_bilibili=true`，或主人正在直接询问本次结果时才向聊天投递。发评论、回复或私信仍须由实际工具动作及其回执确认，收件箱“已处理”不代表发信成功。

本次验收没有使用用户账号试发评论、私信、动态或投稿。

旧 MCP 还会把撤回类私信的 JSON 数字当作对象，导致整个会话读取失败。`companion_bilibili_compat.py` 只修复人物目录中的独立副本，不修改原 DSH 插件；空内容事件不进入模型认知。局部读取失败保留 `error_tool`，不冒充登录失效。

## 迁入云端

首次本地运行复制原插件的 `mcp_server.py` 和 MIT 许可证到人物目录 `data/companion/bilibili/`。人物目录迁移后可以直接从该目录启动，不依赖 Windows 用户插件绝对路径。Linux 在运行核心的 Python 环境安装 `pip install -r requirements-bilibili.txt`；本机优先复用已有 `.venv` 的 MCP 依赖。

画面准备另需系统 **Node.js ≥18 和 ffmpeg**，不需要 yt-dlp、DSH 会话或 npm 包。部署时保留整个 `vendor/bilibili-watch/`，包括 MIT `LICENSE`。`BILI_CREDENTIALS_FILE` 指向人物现有 B 站凭据，`BILI_DATA_HOME` 指向人物视觉缓存目录，不修改系统 HOME、不复制凭据到系统用户通用目录，也不把 Cookie 或带签名的取流 URL 放入 manifest/工具输出。

离线烟测可复用同一 CLI，不需要 B 站账号：

```text
node vendor/bilibili-watch/tools/commands/bili-watch.mjs BV1234567890 3x3 /absolute/output --video /absolute/synthetic.mp4 --duration 9 --uniform
```

本地真实烟测已得到 2160×1215 九宫格，时间点为 0.5、1.5……8.5 秒，九格内容逐一核对；这证明本地素材流程，不替代真实 B 站云端验收。视觉阶段还要求配置的模型实际支持图片输入。

后端在阅读调用或社交轮询时按需启动，顺序处理请求，退出角色时关闭。首次启动或调用超时会关闭进程，下次重新启动；不自动重放有副作用的请求。原始回执存入人物 `data/companion/artifacts/`，已知凭据值在写日志前替换。普通聊天本身不会为了读取完整工具目录、空轮询或维持缓存而额外调用模型。
