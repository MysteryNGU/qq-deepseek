# 记忆与主动陪伴增强

设计与实现日期：2026-10-29。保留 NapCat → Python 宿主 → DSH 的现有链路。
本次独立实现相关机制，没有引入 AstrBot 运行时或复制第三方插件代码。

## 稳定事实

小时整理的 `organized_memory` 提案新增可选 `stable_facts`，每批最多 8 条。
同一次整理模型调用同时提交摘要与事实，不增加独立提取请求。
事实沿用 `memories`、`memory_sources`、`MemoryService.revise_fact`，不另建记忆库。

每条包含 `actor_id`、稳定的 `topic_key`、`quote`、`evidence_refs` 和
`operation: observe|correct|change`。宿主要求证据来自本批已读且纳入摘要的真人消息，
全部属于同一发言人、同一场景，quote 等于完整原始正文，最多 400 字。
多事实消息可映射多个主题，但不截去否定、条件和上下文。长消息保留摘要和原文路径。
是否为稳定事实、转述或角色扮演仍依赖模型语义判断，逐字校验不能代替语义判断。

相同主题和规范化原文合并来源；不同措辞不会被宿主冒险判定为同一事实。
不同值的普通陈述保留冲突状态，只有模型依据明确更正/变化提交 correct/change 时替换旧值。
更正不能使用比当前依据更旧的消息；旧值保留供原文历史读取。
不同并存爱好用不同主题键，不能把所有爱好放在一个互斥键下。
通过校验的事实与摘要原子提交，幂等重放不会重复保存；无效事实单独返回拒绝原因，不阻断可用摘要。
来源遗忘、学习重置、权限检查继续生效。
不自动重整全部历史；新整理批次开始使用该格式，旧数据原样保留。

## 按问题召回与诊断

`life_read(kind:recall,query,intent,diagnostics)` 的 intent 支持：

- `auto`：沿用原有词法、向量和关联混合排序。
- `facts`：在已有匹配候选内优先当前有效事实，不凭空插入无关事实。
- `recent`：按候选的发生时间优先排序，不按整理时间冒充事件时间。
- `history`：保持普通相关性排序；旧版/失效事实需用已知 life_source 引用明确读历史。

diagnostics 返回命中路线、当前页数量、剩余候选数量和空结果说明；事实项带人物、主题和值。
更正后的事实提供当前受众仍有权历史读取的 previous_ref，可用 life_source 沿它查看旧版。
诊断只涉及当前受众可见的候选，不报告隐藏内容、隐藏编号或隐藏候选数量。
分页绑定查询意图与诊断开关，沿用权限版本、来源版本和字数预算。

## 主动联系

`ContactPolicy` 只约束私聊中的纯自发唤醒（idle_probe、motivation、self_scheduled）。
真实用户输入、工具结果、task_due 等明确任务唤醒，以及当前用户来源的任务仍按既有流程执行。
它不改变原有 10～60 分钟的内部空闲唤醒；角色可以醒来做自己的事情而不发送消息。

自发 `life_say` 必须携带 `contact_basis`。followup、shared_experience 或 anniversary
引用本次 sources 中 1～4 条可读取的真实原始事件。念头、定时唤醒和未送达草稿不能当作依据。
依据是否真正适合当前话题和日期由主角色判断，宿主验证来源与权限；不是自动推断纪念日的引擎。

“想念主人”也是独立理由：连接 relatedness 或亲近 intimacy 的当前驱力达到原有表达阈值、
且不在恢复期时，`contact_policy.missing_you` 返回可用的 `{kind:missing_you,dimension,cycle_id}`。
角色可直接把它作为 contact_basis 表达想念，无需外部话题或创建任务。此通道仅针对主人私聊，
不调整驱力数值，不新增强制定时问候；角色仍可选择休息。发送前重查当前周期和需要，旧周期失效。
本轮唤醒仍作为普通 sources 保留，不能把想念写成外部事实。相关待处理动机在真正送达后记录 expressed，
不会自动结算满足；失败或 unknown 保留未完成状态，重放用首次发送时冻结的动机归属。
其他动机依旧需要独立决定。未回应降频、暂停、用户停止及原有发送保护不变；表达自然且不向用户索取回应。

`contact_expressions` 只保存表达编号、场景、遗忘代数、类别、输入序号和时间，不保存聊天正文。
计数从现有 deliveries 的 confirmed 回执计算，每个逻辑表达只计一次；部分实际送达也计一次。
失败、排队和 unknown 不计为对方未回应，unknown 仍受原有禁止盲重发规则保护。
第一次未回应后至少间隔 1 小时，第二次后 4 小时，第三次后暂停自发联系，直到有新的真人消息。
状态可由 `life_read(kind:contact_policy)` 读取，同时进入当前角色上下文。重启保留，场景独立。

连续收尾采用窄规则：已确认送达的最后一条表达是纯晚安/道别，对方也只是纯道别，
30 分钟内拦截再次纯道别并提示主角色用 life_rest 收尾。带新问题、额外内容或媒体不匹配。
此规则在表达前执行，不吞掉用户输入，不绕过画像复核和输入确认；仍可能有一次模型调用。
发送分段前再次检查依据与联系策略，遇到新输入仍由原有发送保护中止并重新理解。

## 日常状态与工具状态

同一人格、同一段关系和记忆，分开呈现日常相处规则与工作执行规则。默认策略为 auto，
初始处于 chat。日常提示保留输入确认、真实记忆、关系与主动联系规则，减少需求收集、
任务汇报式措辞；不常驻命令行工具。进入 tools 后由 `work_context.py` 单独装配工作流程：
不读取、注入人格卡、关系定义/数值、情绪、欲望、专项体验、人物画像和陪伴联想。
仅提供任务与检查点、当前输入、执行回执、能力入口及切回方式；任务需要的历史按来源读取。
子代理使用独立工作说明，向主角色交付证据、产物和阻碍，不加载主角色社交状态。
工具状态的契约投影也移除嵌入式关系评价、画像复核和联系动机等字段，避免这些大段规则
仍经工具 schema 回到工作提示中；完整运行校验与原有权限规则继续生效。
切换同时改变上下文校验戳和工具展示作用域，旧的已加载工具定义不能跨状态继续常驻。
这会减少工作指令对聊天的影响，但不会清空同一会话历史，也不保证模型每次措辞都符合预期。

主人私聊的完整纯文本命令由宿主直接处理，无需模型猜测：

| 命令 | 行为 |
| --- | --- |
| `/工具模式`、`/开启工具状态`、`开启工具状态` | 固定工具状态，直到主人改变选择 |
| `/聊天模式`、`/结束工具状态`、`结束工具状态` | 固定日常状态，暂停当前场景的活跃任务，阻止自行重开 |
| `/自动模式` | 恢复自动切换，先回日常；不会自动恢复已暂停任务 |
| `/模式` | 查看当前状态和切换策略 |

命令不按子串匹配，不从引用、混合媒体、群消息或其他账号获取主人控制权。
状态按 scope 与遗忘代数持久保存，进程重启保留；清空该场景记忆后恢复默认。

角色可用 `life_intent(action:set_mode,mode:tools|chat)` 切换，不创建虚假任务。
自动策略下，实际外部工具调用、媒体生成、咨询或自身修改也会进入工具状态。
有活跃的当前任务、在途操作或任务接续时保持工具状态，避免每个模型轮次反复加载陪伴状态。
任务完成、暂停或等待且没有在途工作后，结束本轮会回日常；角色也可明确调用切回入口。
显式工具策略不会自动退回；显式日常策略不能由角色、子代理或定时唤醒解除。
`life_read(kind:interaction_mode)` 与动态上下文均可读取状态。

日常状态仍能聊天、记忆、回忆、评价感受、想念、发送已有素材及语音表达。
它不是禁用所有内部工具的开关。工具状态也不新增任何权限，不解除原有等待、费用或取消约束。
主人结束工具状态后，会请求取消该会话的主执行链、子代理、咨询与媒体任务；停止失败时明确提示。
已派发的外部操作可能仍需等待停止或核对结果，已经完成的修改不会自动撤销。
重新开启仅解除模式限制，用户暂停的任务仍需新的明确恢复指令。

工作期间遇到的待复核画像保持 pending，并标为 deferred_tool_mode；日常状态后续轮次重新
呈现这些来源，不伪造“已复核”。工作结果提交不以完成关系/动机分析为前提，任务进度检查仍执行。

## 唤醒后的执行接续

合并远端 `5708bd5b` 的空闲解冻修复，旧 unknown 操作不再永久阻止下一次空闲计时。
自动归档仅限确定的只读工具；命令行、写入及未知插件仍保留 unknown，不能当失败后重放。

真实 task_due 唤醒进入宿主时，绑定该场景仍可执行的任务和最新版本，并进入工具状态。
明确聊天锁、取消、暂停、等待和跨场景限制仍有效，旧唤醒不能恢复这些任务。
`execution_mode`、`result_sources`、`activity_blocker` 补齐到模型使用的契约中，分别支持
持续执行、提交真实结果和保存阻碍，避免宿主要求的合法操作被 schema 拒绝。

结束一轮任务唤醒前，检查所有到期任务的真实执行记录；普通任务也不能只休息而无进展。
有在途操作由原结果链处理，有新成功结果就安排下一步；已经完成、暂停或等待的任务不再推进。
无进展可显式保存具体 activity_blocker 并按现有冷却后复查，或暂停/等待；不是把计划当执行。
普通 idle_probe 仍可选择休息，不强制创建任务；提示明确允许基于兴趣发起行动，不以没有新消息为阻碍。

此实现精简新的系统与状态提示，不清除聊天历史，也不隔离已经进入历史的文字。
本地数据库没有近期的运行回执，本次根据可复现的契约与接续缺口修复；真实模型的行动选择仍需上线观察。
