# 多人物网页管理

2026-10-30：采用多个独立人物同时运行的方式，取代之前的全局人格切换方案。

## 使用方式

打开本机设置页 `http://127.0.0.1:6100/`，登录后进入“人物管理”。管理密码仍在 `data/settings/login.txt`。

本机已直接登记三位独立人物，不是仅把卡片放入模板，顺序为：

| 人物 | 固定编号 | 人格源文件 |
| --- | --- | --- |
| 原始小鱼 | `xiaoyu` | `personas/xiaoyu.md` |
| 卡夫卡 | `kafka` | `personas/kafka.md` |
| 流萤 | `firefly` | `personas/firefly.md` |

三位人物目前均为“待配置 QQ”，记忆为空、未启动。点击各自的“配置 QQ 与人格”即可继续。人物 QQ 和连接地址可以暂时留空保存，补齐之后才能启动。原始小鱼保留原来的身份与性格，调整了服务口吻，亲密栏目保留空位；卡夫卡使用自己的身份，不再自称小鱼。恢复原始小鱼的卡片不恢复旧数据库，也不重新启用旧主实例。

1. 点击“新建人物”，填写固定人物编号、显示名称、她使用的 QQ、主人 QQ、独立 OneBot WebSocket 地址与连接密钥。
2. 选择原始小鱼、卡夫卡、流萤或空白模板，直接编辑人格卡。已保存卡片里的亲密栏目和占位会完整保留。
3. 建立后默认停止，点击该人物卡片上的“启动”。每个人物可分别启动、停止，也可同时运行。
4. 在各自的“参数设置”中修改模型、接收范围、驱动力和运行参数。保存后点击该人物的“重启”，等待当前操作结束再加载。
5. 修改 QQ 绑定或人格全文前先停止这个人物，编辑保存后重新启动。停止与重新启动不清空记忆。

新人物在创建时将主目录中的可复用配置展开为自己的配置快照：模型与工具连接、记忆整理、画像复核、上下文策略、本地向量、语音和生图、咨询配置及动力参数。缺省项也写出实际默认值；它们不是持续引用主目录的动态继承。API 密钥仅保存在本机并遮蔽回显；之后可以分别修改。

每个人物仍保留独立 QQ、人格、记忆、关系、任务和当前情绪。不会复制旧联系人画像、私人学习方法、当前动力值或亲密互动状态。固定合成音色素材可复制，导入与默认音色的运行记录分别保存。

本机三个人物的功能配置已于 2026-10-31 补齐：向量服务分别使用 8231、8232、8233 端口，共用只读模型文件；音色清单、音频素材、咨询请求目录及媒体任务目录位于各自部署内。原有的小鱼 QQ 绑定保留，卡夫卡和流萤的 QQ 账号与连接需用户填写。

静态联系配置也已恢复：每个人物有原配置中的 2 个允许好友、2 个允许群，以及从当前 QQ 读取补充的 3 个名称映射。名称和白名单可作为配置复用，不等于已经与这些人建立相同的熟悉程度、信任、承诺或共享记忆。后续新建人物同样复制静态联系配置，关系与经历仍从各自记录形成。

曾随旧资料隔离的 IndexTTS、sd.cpp 及其 Python 运行时已恢复为共用程序目录，未恢复旧聊天和生成任务。配置修改前的快照保存在 `data/settings/config-backups/20261031-complete-character-settings`。

QQ 连接需要用户事先为每个账号运行对应的 NapCat/OneBot 实例；每个实例配置不同的 WebSocket 端口。QQ 扫码登录由对应 NapCat 完成，人物管理页负责人物 Bot 的运行，不自动安装或代替 NapCat 登录。

## 运行与数据归属

每个人物拥有自己的部署目录：

```text
data/characters/
  registry.json               # 人物登记与期望运行状态
  firefly/
    bot.py                    # 创建时复制的程序快照
    life/
    tests/
    scripts/codex_consult.py
    config.toml
    persona.md
    life-dynamics.json
    data/
      bot.lock
      life.db                 # 独立记忆、关系、情绪与任务
      dsh-home/               # 独立模型会话与插件 profile
      life-control/           # 独立健康回报与发布记录
      settings/               # 独立重启请求与参数版本
      media/
      logs/
  kafka/
    ...
```

程序复制只包含公开程序文件、测试和必要的启动入口。不会复制主实例的数据库、私人人格、技能、记忆、媒体或 DSH home。人物创建后使用自己的程序快照，普通重启不会覆盖其程序或自我修改；主项目代码更新也不会自动覆盖所有人物的快照。

管理页复用已有 `HostSupervisor` 与受控进程树，每个人物独立持有监督器。一个人物停止或崩溃，不应停止其他人物。管理服务重启后，根据登记的期望状态重新启动先前运行的人物；先前已停止的人物保持停止。

同一个 QQ 或等价的连接地址不能重复绑定；未配置的草稿不占用账号和端点。原主实例退役后释放原连接。Bot 在开始认知活动前，通过 OneBot `get_login_info` 核对实际账号。账号未核验或不一致时，不接收该连接的消息进入记忆，也不允许工具读写该 QQ 通道。

数据库路径、人物身份、DSH home 不能通过普通参数保存接口重绑。人物绑定编辑有版本检查，且要求停止。新人物默认从空白记忆开始；同一个用户与各个人物的关系分别形成，不继承其他人物的共同经历。

应用层记忆、会话和运行文件彼此独立。当前人物工具仍沿用本机原有的广泛文件权限，不提供操作系统级沙箱；不能把这套分目录设计称为对恶意文件读取的安全隔离。

用户已授权移除旧小鱼。本机以 `data/characters/primary-retired.json` 停用原人物，原启动入口只启动管理页，不能重新创建旧人物。全局配置仅保留默认模型、工具和主人账号等设置，原 QQ 绑定、联系人列表和动力状态已清除。

批量永久删除被自动审批以 `blocked by policy` 拦截，命令未执行。随后改为可恢复移动：旧人格、记忆库、会话、日记、日志、迁移备份与生成历史已移出运行目录，保存在 `D:/projects/retired-xiaoyu-20261030`；该目录含恢复清单。没有永久擦除。两张新卡、独立人物目录、管理页认证、模型和工具程序保留。

## 网页与后端入口

- `life/character_manager.py`：人物创建、配置、独立部署、进程监督和恢复。
- `life/character_defaults.py`：展开通用默认值、转换共享模型路径、分离音色清单与咨询记录目录。
- `life/settings_web.py`：复用现有本机认证、Origin 和 CSRF 校验，新增人物接口。
- `life/settings_ui/characters.js`：人物列表、编辑器与运行控制。
- `life/settings_ui/app.js`：主实例和各人物参数设置的明确作用域。
- `life/role_config.py`、`life/role_host.py`：预期人物 QQ 与实际连接账号核验。

接口包括 `/api/characters`、`/api/characters/{id}`，以及各人物的 `/settings`、`/status`、`/save`、`/start`、`/stop`、`/restart`。所有人物配置与操作接口均要求管理登录；修改要求 CSRF 校验，不提供任意命令执行接口。
